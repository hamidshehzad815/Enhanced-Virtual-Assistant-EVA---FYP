================================================================
REDIS STATE STRUCTURE FOR DELETE
================================================================

  Key    : "context:{user_id}"
  TTL    : 300 seconds

  {
    expected_response : "free_text" | "number" | "yes_no",
    pending_action    : {
      intent   : "delete",
      task_ids : [ list of matched task_ids ],
      tasks    : [ { title, due_datetime, priority } ... ],
      bulk     : true | false,
      entities : { ...original extracted entities... }
    }
  }


================================================================
ALL PENDING STATES FOR DELETE COMMAND
================================================================

  State 1 — no entity given, asking user to specify
  ────────────────────────────────────────────────────
  {
    expected_response : "free_text",
    pending_action    : {
      intent   : "delete",
      task_ids : [],
      tasks    : [],
      bulk     : false,
      entities : {}
    }
  }
  EVA asked: "Which task would you like to delete, Ali?
              You can say the name, date, or priority."


  State 2 — 1 match found, awaiting yes/no
  ────────────────────────────────────────────────────
  {
    expected_response : "yes_no",
    pending_action    : {
      intent   : "delete",
      task_ids : [ "task_id_1" ],
      tasks    : [{ title: "Physics exam",
                    due_datetime: "2026-03-23T17:00:00",
                    priority: "high" }],
      bulk     : false,
      entities : { task_name: "physics exam" }
    }
  }
  EVA asked: "I found Physics exam on Monday at 5PM.
              Want me to delete it?"


  State 3 — 2-5 matches found, awaiting number or "all"
  ────────────────────────────────────────────────────
  {
    expected_response : "number",
    pending_action    : {
      intent   : "delete",
      task_ids : [ "id1", "id2", "id3" ],
      tasks    : [
        { title: "Physics exam",  due_datetime: "...", priority: "high" },
        { title: "Physics lab",   due_datetime: "...", priority: "medium" },
        { title: "Physics quiz",  due_datetime: "...", priority: "low" }
      ],
      bulk     : false,
      entities : { priority: "high" }
    }
  }
  EVA asked: "I found 3 tasks, Ali. Which one?
              1. Physics exam — Monday 5PM (high)
              2. Physics lab — Tuesday 3PM (medium)
              3. Physics quiz — Wednesday 2PM (low)
              Or say 'all' to delete all of them."


  State 4 — user chose "all", awaiting bulk confirmation
  ────────────────────────────────────────────────────
  {
    expected_response : "yes_no",
    pending_action    : {
      intent   : "delete",
      task_ids : [ "id1", "id2", "id3" ],
      tasks    : [ ...all 3 tasks... ],
      bulk     : true,
      entities : { priority: "high" }
    }
  }
  EVA asked: "Just to confirm — delete all 3 Physics tasks?
              This cannot be undone."


================================================================
CONTEXT MANAGER DECISION FLOW
================================================================

  Input arrives at AI server
       ↓
  PREPROCESSING (lowercase + too_short check)
       ↓
  Redis state already fetched (from self-fetch)
       │
       ├── NO pending state
       │   → pass to Model 1 normally
       │
       └── pending state EXISTS
               ↓
           CHECK CANCEL FIRST
           cancel / stop / abort / never mind /
           forget it / leave it / discard / no cancel
               │
               ├── YES
               │   → AI server clears Redis
               │   → Gemini: "No problem Ali,
               │              nothing was deleted."
               │   → return to Node.js → STOP
               │
               └── NO
                     │
                     ├── expected = free_text (State 1)
                     │     → SKIP Model 1
                     │     → handle reply directly
                     │
                     ├── expected = yes_no (State 2 or 4)
                     │     → RUN Model 1
                     │     → handle based on result
                     │
                     └── expected = number (State 3)
                           → RUN Model 1
                           → handle based on result


================================================================
FREE TEXT HANDLING — STATE 1
================================================================

  Why Model 1 skipped:
  Reply like "physics exam" has no command structure.
  Model 1 would misclassify it. We know we are waiting
  for a task identifier from Redis state.

  User replies: anything

  → treat entire reply as task_name
  → merge into pending_action.entities as task_name
  → AI server clears Redis
  → re-enter handler from STEP 1
  → handler now has task_name → queries DB → continues


================================================================
YES/NO HANDLING — STATE 2 (single match confirm)
================================================================

  Why Model 1 runs first:
  "yes" could begin a new command. Model 1 confirms
  it is a confirmation intent first.

  Model 1 runs:

    → command / multiple_command:
        Redis stays (TTL resets)
        Gemini: "I'm still waiting — want me to delete
                 Physics exam? Just yes or no, Ali."
        STOP

    → general / out_of_scope:
        Redis stays (TTL resets)
        Gemini: "Just a yes or no will do, Ali."
        STOP

    → confirmation → proceed:

  YES keywords:
  yes / yeah / yep / sure / go ahead / do it / confirm / ok
  → AI server clears Redis
  → jump to STEP 5 of delete handler (perform deletion)
  → delete the single task in task_ids

  NO keywords:
  no / nope / nah / don't / leave it / keep it
  → AI server clears Redis
  → Gemini: "No problem, I left Physics exam as it is."
  → STOP

  Unrecognised confirmation:
  → Redis stays (TTL resets)
  → Gemini: "Just a yes or no will do, Ali."
  → STOP


================================================================
NUMBER HANDLING — STATE 3 (multiple matches, pick one)
================================================================

  Why Model 1 runs first:
  "1" or "2" could be a task name or other input.
  Model 1 confirms it is a confirmation intent first.

  Model 1 runs:

    → command / multiple_command:
        Redis stays (TTL resets)
        Gemini: "I'm still waiting for your choice.
                 Say cancel to stop."
        STOP

    → general / out_of_scope:
        Redis stays (TTL resets)
        Gemini: "Pick a number from the list, or say
                 'all', Ali."
        STOP

    → confirmation → proceed:

  Valid number (1 to N where N = len(task_ids)):
  → get selected_task = tasks[number - 1]
  → update Redis:
      expected_response = "yes_no"
      task_ids          = [ selected_task_id ]
      tasks             = [ selected_task ]
      bulk              = false
  → Gemini: "Got it — delete Physics exam on Monday at 5PM?"
  → STOP
  → next reply handled as State 2

  "all" keyword:
  trigger: "all" / "all of them" / "delete all" /
           "every one" / "all tasks"
  → update Redis:
      expected_response = "yes_no"
      bulk              = true
      task_ids and tasks stay the same (all matches)
  → Gemini: "Just to confirm — delete all 3 Physics tasks?
             This cannot be undone."
  → STOP
  → next reply handled as State 4

  Number out of range:
  → Redis stays (TTL resets)
  → Gemini: "That number is not on the list, Ali.
             Pick between 1 and [N], or say 'all'."
  → STOP

  Anything else:
  → Redis stays (TTL resets)
  → Gemini: "Pick a number from the list or say
             'all' to delete everything, Ali."
  → STOP


================================================================
YES/NO HANDLING — STATE 4 (bulk confirmation)
================================================================

  Same Model 1 routing as State 2.

  YES keywords:
  → AI server clears Redis
  → jump to STEP 5 of delete handler
  → bulk = true → delete ALL task_ids in pending state
  → Gemini: "Done Ali — all 3 Physics tasks have been
             cleared from your schedule."
  → STOP

  NO keywords:
  → AI server clears Redis
  → Gemini: "No problem, I left all those tasks as they are."
  → STOP

  Unrecognised:
  → Redis stays (TTL resets)
  → Gemini: "Just a yes or no, Ali."
  → STOP


================================================================
CROSS CUTTING CASES (apply to ALL states)
================================================================

CANCEL — always checked first
────────────────────────────────────────────────────────────
  cancel / stop / abort / never mind / forget it /
  forget that / leave it / discard / no cancel

  → AI server clears Redis
  → Gemini: "No problem Ali, nothing was deleted."
  → STOP


NEW COMMAND WHILE PENDING — yes_no and number only
────────────────────────────────────────────────────────────
  (free_text state skips Model 1 — not applicable there)

  Model 1 returns command / multiple_command:
  → Redis stays (TTL resets)
  → Gemini: "I'm still waiting for your reply, Ali.
             Say cancel if you want to start fresh."
  → STOP


TTL EXPIRY — all states
────────────────────────────────────────────────────────────
  User silent for 300 seconds
  → Redis auto-expires
  → next input starts pipeline fresh
  → no message needed
