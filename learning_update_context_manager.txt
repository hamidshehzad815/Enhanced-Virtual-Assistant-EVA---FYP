================================================================
CONTEXT MANAGER — LEARNING UPDATE COMMAND (FINAL)
Runs inside AI Server — Redis managed by AI Server directly
================================================================

DECISIONS LOCKED
================================================================

  1. Context manager runs BEFORE Model 1 on every input
  2. Redis state fetched at request start (self-fetch)
  3. Hybrid approach based on expected_response:
       free_text → skip Model 1, handle reply directly
       yes_no    → run Model 1 first, then handle
       number    → run Model 1 first, then handle
  4. Cancel checked FIRST before anything else
  5. TTL = 300 seconds, reset on every Redis write
  6. All Gemini replies natural, specific, use user name
  7. Sub-intents: pause, resume, complete, skip, reschedule
  8. Each sub-intent has its own Redis states and flow


================================================================
REDIS STATE STRUCTURE FOR LEARNING UPDATE
================================================================

  Key    : "context:{user_id}"
  TTL    : 300 seconds

  {
    expected_response : "free_text" | "number" | "yes_no",
    pending_action    : {
      intent     : "learning_update",
      sub_intent : "pause" | "resume" | "complete" |
                   "skip" | "reschedule",
      stage      : "identify" | "confirm" |
                   "new_date" | "identify_language",
      goal_id    : null or identified goal_id,
      goal       : null or { title, roadmap_key,
                             status, completed_topics,
                             total_topics },
      goal_ids   : [] or [ matched goal_ids ],
      goals      : [] or [ matched goal summaries ],
      entities   : { ...extracted entities... }
    }
  }


================================================================
ALL PENDING STATES
================================================================

  ── PAUSE / RESUME STATES ───────────────────────────────────

  State 1 — no identifier given (pause or resume)
  ────────────────────────────────────────────────────────
  {
    expected_response : "free_text",
    pending_action    : {
      intent     : "learning_update",
      sub_intent : "pause" or "resume",
      stage      : "identify",
      goal_ids   : [],
      goals      : [],
      entities   : {}
    }
  }
  EVA asked (pause):  "Which learning goal would you
                       like to pause, Ali?"
  EVA asked (resume): "Which learning goal would you
                       like to resume, Ali?"


  State 2 — multiple goals found (pause or resume)
  ────────────────────────────────────────────────────────
  {
    expected_response : "number",
    pending_action    : {
      intent     : "learning_update",
      sub_intent : "pause" or "resume",
      stage      : "identify",
      goal_ids   : [ "id1", "id2" ],
      goals      : [
        { title: "Python basics", roadmap_key: "basics",
          status: "active", completed_topics: 3,
          total_topics: 8 },
        { title: "Python functions", roadmap_key: "functions",
          status: "active", completed_topics: 0,
          total_topics: 5 }
      ],
      entities   : { topic: "Python" }
    }
  }
  EVA asked: "I found 2 Python goals, Ali. Which one?
              1. Python basics — active — 3/8 done
              2. Python functions — active — 0/5 done"


  State 3 — goal identified, awaiting confirmation
  ────────────────────────────────────────────────────────
  {
    expected_response : "yes_no",
    pending_action    : {
      intent     : "learning_update",
      sub_intent : "pause" or "resume",
      stage      : "confirm",
      goal_id    : "identified_goal_id",
      goal       : { title, roadmap_key, status,
                     completed_topics, total_topics },
      entities   : { topic: "Python", subtopic: "basics" }
    }
  }
  EVA asked (pause):  "Pause Python basics, Ali? Your
                       progress will be saved."
  EVA asked (resume): "Resume Python basics, Ali? I'll
                       rebase your schedule from today."


  ── COMPLETE / SKIP / RESCHEDULE STATES ─────────────────────

  State 4 — multiple roadmaps, need language identification
  ────────────────────────────────────────────────────────
  {
    expected_response : "number",
    pending_action    : {
      intent     : "learning_update",
      sub_intent : "complete" | "skip" | "reschedule",
      stage      : "identify_language",
      goal_ids   : [ "id1", "id2" ],
      goals      : [ ...active goal summaries... ],
      entities   : { date: "next Monday" }
                    (for reschedule — date already extracted)
    }
  }
  EVA asked (complete): "You have multiple active learning
                         goals, Ali. Which one?
                         1. Python basics — session 3 next
                         2. MySQL advanced — session 2 next"
  EVA asked (skip):     same format
  EVA asked (reschedule): same format


  State 5 — reschedule, need new date
  ────────────────────────────────────────────────────────
  {
    expected_response : "free_text",
    pending_action    : {
      intent     : "learning_update",
      sub_intent : "reschedule",
      stage      : "new_date",
      goal_id    : "identified_goal_id",
      goal       : { title, roadmap_key, ... },
      entities   : {}
    }
  }
  EVA asked: "What date would you like to move
              your Python session to, Ali?
              Your learning days are Monday
              and Wednesday."


================================================================
CONTEXT MANAGER DECISION FLOW
================================================================

  Input arrives at AI server
       ↓
  PREPROCESSING (lowercase + too_short check)
       ↓
  Redis state already fetched (from self-fetch)
       │
       ├── NO pending state
       │   → pass to Model 1 normally
       │
       └── pending state EXISTS
               ↓
           CHECK CANCEL FIRST
           cancel / stop / abort / never mind /
           forget it / leave it / discard / no cancel
               │
               ├── YES
               │   → AI server clears Redis
               │   → EVA: "No problem Ali,
               │           nothing was changed."
               │   → STOP
               │
               └── NO
                     │
                     ├── expected = free_text
                     │   (State 1 or State 5)
                     │     → SKIP Model 1
                     │     → route by stage + sub_intent
                     │
                     ├── expected = number
                     │   (State 2 or State 4)
                     │     → RUN Model 1
                     │     → handle based on result
                     │
                     └── expected = yes_no (State 3)
                           → RUN Model 1
                           → handle based on result


================================================================
FREE TEXT HANDLING — STATE 1 (stage: identify)
================================================================

  Sub-intent = pause or resume
  Why Model 1 skipped:
  Reply like "Python" or "Python basics" has no
  command structure. We know what we are waiting for.

  User replies: anything

  → pass reply through NER
  → extract topic + subtopic
  → topic not found:
      Redis stays (TTL resets)
      EVA: "I didn't catch that. Which learning
            goal would you like to [pause/resume]?
            Try saying the topic name, Ali."
      STOP

  → topic found:
      normalize via TOPIC_ALIAS_MAP
      subtopic present → map via SUBTOPIC_ALIAS_MAP
                         + regex search
      merge into entities
      clear Redis
      re-enter handler from STEP 1
      handler queries DB with new entities


================================================================
FREE TEXT HANDLING — STATE 5 (stage: new_date)
================================================================

  Sub-intent = reschedule
  Why Model 1 skipped:
  Reply like "next Monday" is not a command.
  We are waiting for a new date.

  User replies: anything

  → pass reply to Duckling
  → Duckling fails:
      Redis stays (TTL resets)
      EVA: "I didn't catch that date. Try something
            like 'next Monday' or '25th May', Ali."
      STOP

  → Duckling resolves:
      Validation 1 — is date in the past?
        resolved date < today:
          Redis stays (TTL resets)
          EVA: "That date has already passed.
                When would you like to reschedule
                to, Ali?"
          STOP

      Validation 2 — is date on a learning schedule day?
        check resolved date weekday against
        preferred_learning_schedule days
        not a learning day:
          Redis stays (TTL resets)
          EVA: "That day is not one of your learning
                days, Ali. Your available days are
                [day list]. Which one works?"
          STOP

      Validation 3 — date is valid learning day:
        clear Redis
        re-enter handler at STEP reschedule execution
        with new date confirmed


================================================================
NUMBER HANDLING — STATE 2 (multiple goals, pause/resume)
================================================================

  Why Model 1 runs first:
  "1" or "2" could be a topic name. Model 1 confirms
  it is confirmation intent first.

  Model 1 runs:

    → command / multiple_command:
        Redis stays (TTL resets)
        EVA: "I'm still waiting for your choice.
              Say cancel to stop, Ali."
        STOP

    → general / out_of_scope:
        Redis stays (TTL resets)
        EVA: "Pick a number from the list, Ali."
        STOP

    → confirmation → proceed:

  Valid number (1 to N):
  → get selected_goal = goals[number - 1]
  → update Redis:
      expected_response = "yes_no"
      stage    = "confirm"
      goal_id  = selected_goal_id
      goal     = selected_goal
      remove goal_ids and goals arrays
  → Gemini generates confirmation question
  → STOP

  Number out of range:
  → Redis stays (TTL resets)
  → EVA: "That number is not on the list, Ali.
          Pick between 1 and [N]."
  → STOP

  Anything else:
  → Redis stays (TTL resets)
  → EVA: "Pick a number from the list, Ali."
  → STOP


================================================================
NUMBER HANDLING — STATE 4 (multiple roadmaps, complete/skip/reschedule)
================================================================

  Same Model 1 routing as State 2.

  Valid number:
  → get selected_goal = goals[number - 1]
  → clear Redis
  → re-enter handler with identified goal
  → handler proceeds with sub-intent execution

  Number out of range / invalid:
  → Redis stays (TTL resets)
  → EVA: "Pick a number from the list, Ali."
  → STOP


================================================================
YES/NO HANDLING — STATE 3 (confirm pause/resume)
================================================================

  Why Model 1 runs first:
  "yes" could begin a new command.

  Model 1 runs:

    → command / multiple_command:
        Redis stays (TTL resets)
        EVA: "I'm still waiting — should I
              [pause/resume] [goal name]?
              Yes or no, Ali."
        STOP

    → general / out_of_scope:
        Redis stays (TTL resets)
        EVA: "Just a yes or no, Ali."
        STOP

    → confirmation → proceed:

  YES keywords:
  yes / yeah / yep / sure / go ahead / confirm / ok
  → AI server clears Redis
  → execute pause or resume operation

  NO keywords:
  no / nope / nah / don't / leave it
  → AI server clears Redis
  → EVA: "No problem, [goal name] stays
          as it is, Ali."
  → STOP

  Unrecognised:
  → Redis stays (TTL resets)
  → EVA: "Just a yes or no, Ali."
  → STOP


================================================================
CROSS CUTTING CASES
================================================================

CANCEL — always checked first, all states
────────────────────────────────────────────────────────────
  cancel / stop / abort / never mind / forget it /
  forget that / leave it / discard / no cancel

  → AI server clears Redis
  → EVA: "No problem Ali, nothing was changed."
  → STOP


NEW COMMAND WHILE PENDING
────────────────────────────────────────────────────────────
  free_text states → Model 1 skipped
    → reply treated as expected value
    → if extraction fails → ask again naturally

  yes_no and number states → Model 1 runs
    → command detected → blocked
    → EVA: "I'm still waiting for your reply, Ali.
            Say cancel to start fresh."
    → STOP


TTL EXPIRY — all states
────────────────────────────────────────────────────────────
  User silent for 300 seconds
  → Redis auto-expires
  → next input starts fresh
  → no message needed


================================================================
GEMINI REPLY GUIDELINES
================================================================

  WRONG — never use:
  × "Goal paused successfully."
  × "Invalid input. Please try again."
  × "Confirmation required."
  × "Session marked complete."

  CORRECT — what EVA says:
  ✓ "Which learning goal would you like to pause, Ali?"
  ✓ "Pause Python basics, Ali? Your progress is saved."
  ✓ "Python basics is paused, Ali. Resume whenever
     you're ready."
  ✓ "Welcome back Ali! I've rescheduled your remaining
     Python sessions starting next Monday."
  ✓ "Great work Ali — Python session 3 is marked
     complete. Session 4 is up next on Wednesday."
  ✓ "Skipped Python session 2, Ali. Session 3 has
     moved to Monday — no time wasted."
  ✓ "Done Ali — Python session 3 moved to next
     Monday at 6PM."
