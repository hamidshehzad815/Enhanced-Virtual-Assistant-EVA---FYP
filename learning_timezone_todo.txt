ROOT CAUSE (why 09:40 became 2:40 PM in Asia/Karachi)
================================================================

  Convention in EVA:
    • User-facing slot times (Settings learning schedule) = LOCAL wall clock
      in user timezone (e.g. Asia/Karachi 09:40 = 9:40 AM).
    • MongoDB `tasks.due_datetime` and session `scheduled_date` = UTC-naive
      instant (physics exam 5 PM Karachi → 12:00 UTC stored) ✓

  Bug:
    • `build_schedule()` used `datetime.combine(date, HH:MM)` with NO timezone
      conversion → 09:40 was saved as 09:40 UTC → displays as 2:40 PM PKT.
    • `scheduling_add` already used `local_datetime_to_utc_naive()` ✓
    • Learning reschedule in `update.py` also used naive `datetime.combine` ✗
    • Python conflict helper `_weekday_and_minutes` treated UTC-naive as LOCAL ✗

  Your data example (before fix):
    Slot Fri 09:40 PKT  →  stored 2026-06-05T09:40:00.000Z  →  2:40 PM PKT ✗
    Slot Mon 18:00 PKT  →  stored 2026-06-08T18:00:00.000Z  →  11:00 PM PKT ✗
    Physics Mon 5 PM PKT → stored 2026-06-08T12:00:00.000Z  →  5:00 PM PKT ✓
