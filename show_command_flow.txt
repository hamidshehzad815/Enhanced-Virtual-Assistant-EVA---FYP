================================================================
NER ENTITIES FOR SHOW
================================================================

  Extracted from original cased text:
    date     → specific date, relative date, or range keyword
    priority → low / medium / high
    status   → pending / ongoing / complete
    subject  → subject/keyword filter on task title

  NOTE: No task_name for show — user wants a list, not
  a specific task. Subject acts as keyword search on title.

  Examples:
    "show my tasks for Monday"
      → date: "Monday"

    "show high priority tasks"
      → priority: "high"

    "what do I have today"
      → date: "today"

    "show pending tasks for this week"
      → status: "pending", date: "this week"

    "show my physics tasks"
      → subject: "physics"

    "show all tasks" / "what are my tasks"
      → no entities → show all upcoming

    "show completed tasks"
      → status: "complete"

    "show high priority tasks for this week"
      → priority: "high", date: "this week"

================================================================
STEP 1 — RESOLVE DATE FILTER
================================================================

  ┌─────────────────────────────────────────────────────────┐
  │ date present                                            │
  │                                                         │
  │ → pass to Duckling                                      │
  │ → resolve based on grain:                               │
  │                                                         │
  │   grain = day:                                          │
  │     start = start_of_day (user timezone) → UTC          │
  │     end   = end_of_day   (user timezone) → UTC          │
  │     display_label = "Monday" / "today" / "tomorrow"     │
  │                                                         │
  │   grain = week:                                         │
  │     start = Monday 00:00 of that week (user tz) → UTC   │
  │     end   = Sunday 23:59 of that week (user tz) → UTC   │
  │     display_label = "this week" / "next week"           │
  │                                                         │
  │   grain = month:                                        │
  │     start = 1st of month 00:00 (user tz) → UTC          │
  │     end   = last day 23:59 (user tz) → UTC              │
  │     display_label = "this month"                        │
  │                                                         │
  │ → store: { start_utc, end_utc, display_label }          │
  │ → continue to STEP 2                                    │
  └─────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────┐
  │ date absent                                             │
  │ → no date range filter                                  │
  │ → query will use: due_datetime >= now_utc               │
  │   (show upcoming tasks only, not past)                  │
  │ → continue to STEP 2                                    │
  └─────────────────────────────────────────────────────────┘


================================================================
STEP 2 — QUERY TASKS
================================================================

  query = {
    owner_id   : user_id,
    is_deleted : false
  }

  if date resolved:
    query["due_datetime"] = { $gte: start_utc, $lte: end_utc }
  else:
    query["due_datetime"] = { $gte: now_utc }

  if priority present:
    query["priority"] = priority

  if status present:
    query["status"] = status
    NOTE: if status = "complete", remove due_datetime filter
          completed tasks may be in the past

  if subject present:
    query["title"] = { $regex: subject, $options: "i" }

  results     = db.tasks.find(query).sort({ due_datetime: 1 }).limit(10)
  total_count = db.tasks.countDocuments(query)

================================================================
SPECIAL CASES
================================================================

  "show overdue tasks"
  → status = "pending" + due_datetime < now_utc
  → special Duckling not needed — handled in query logic
  → Gemini labels them as overdue in reply

  "show completed tasks"
  → status = "complete"
  → remove upcoming filter (completed may be in past)
  → sorted by due_datetime desc (most recently completed first)

  "show tasks for this week"
  → week grain → Monday to Sunday in user timezone

  "show all tasks" / "what are my tasks"
  → no entities extracted
  → query: due_datetime >= now, no other filter
  → show upcoming only
