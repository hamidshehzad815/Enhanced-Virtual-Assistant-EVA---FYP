================================================================
EVA — ROADMAP SCHEMA, STRUCTURE AND DB SEEDING
Complete reference for roadmap data management
================================================================

OVERVIEW
================================================================

  Two sources of truth for learning roadmaps:

  1. roadmaps.json (file on AI server)
     → defines structure only
     → topic names, levels, session count
     → never changes at runtime
     → owned by developer, updated manually

  2. roadmap_resources (MongoDB collection)
     → seeded FROM roadmaps.json (one time)
     → adds YouTube resources to each topic
     → auto-refreshed every 30 days
     → read by learning add handler at runtime

  Relationship:
  roadmaps.json → seed script → roadmap_resources (MongoDB)
                                        ↓
                              YouTube fetch script
                                        ↓
                              resources attached to each topic


================================================================
ROADMAPS.JSON STRUCTURE
================================================================

  File location (resolution order — see ``get_roadmaps_json_path()`` in ``config/settings.py``):

    1. ``ROADMAPS_JSON_PATH`` environment variable (absolute, or relative to repo root)
    2. ``<repo root>/Roadmaps/roadmaps.json`` if that file exists
    3. ``Eva_AI_Server/data/roadmaps.json`` (fallback)

  {
    "topics": ["Python", "JavaScript", ...],  ← all 20 supported

    "Python": {
      "topics": [                             ← all available levels
        "basics",
        "intermediate",
        "advanced",
        "variables and data types",
        "control flow",
        ...
      ],

      "basics": {
        "days": 8,                            ← suggested calendar-day span for this level
        "topics": [                           ← one session per entry (YouTube-searchable titles)
          "Python Introduction Versions Python 3 vs 2",
          "Python Installation pyenv conda official installer",
          "Python Hello World print and interactive REPL",
          ...
        ]
      },

      "intermediate": {
        "days": 14,
        "topics": [ ... ]
      },

      "advanced": {
        "days": 20,
        "topics": [ ... ]
      },

      "variables and data types": {
        "days": 4,
        "topics": [ ... ]
      },

      ...more specific subtopics...
    },

    "JavaScript": { ... },
    "MySQL": { ... },
    ...
  }

  IMPORTANT RULES FOR JSON:
  → ``days`` = suggested **calendar-day span** for that level (how long the track is meant to run on a calendar).
  → ``topics`` array = one string per **learning session**; ``len(topics)`` is the session count (may differ from ``days``).
  → Optional density: average sessions per calendar day ≈ ``len(topics) / days`` when both are set (e.g. 10 sessions in 5 days ≈ 2/day).
  → every topic title must be specific and YouTube-searchable
  → topic title must include the language/database name
  → general roadmap to be added later (not yet in file)


================================================================
ROADMAP_RESOURCES COLLECTION SCHEMA
================================================================

  Collection  : roadmap_resources
  Owned by    : AI Server (full read/write)
  Node.js     : never touches this collection

  Document structure:
  ─────────────────────────────────────────────────────────
  {
    _id          : ObjectId           unique identifier
    language     : String             "Python"
    level        : String             "basics"
    order        : Number             1, 2, 3... (position in roadmap)
    title        : String             "Python Introduction Versions Python 3 vs 2"
    level_calendar_days : Number or null   copy of JSON ``days`` for this level (same on all rows in the level)
    resources    : [                  YouTube results (empty until fetched)
      {
        title     : String            "Python Tutorial for Beginners"
        url       : String            "https://youtube.com/watch?v=..."
        thumbnail : String            "https://img.youtube.com/vi/.../hqdefault.jpg"
        channel   : String            "Corey Schafer"
      }
    ]
    fetched_at   : Date or null       null until first YouTube fetch
    created_at   : Date               when seeded
    updated_at   : Date               when resources last updated
  }

  Indexes:
  ─────────────────────────────────────────────────────────
  { language: 1, level: 1, order: 1 }   fetch full roadmap in order
  { language: 1, level: 1 }             fetch all topics for a level
  { fetched_at: 1 }                     refresh job query


================================================================
RELATIONSHIP BETWEEN JSON AND MONGODB
================================================================

  roadmaps.json                    roadmap_resources (MongoDB)
  ─────────────────────────────────────────────────────────
  language: "Python"           →   language: "Python"
  level: "basics"              →   level: "basics"
  topics[0]: "Python Intro..." →   order: 1, title: "Python Intro..."
  topics[1]: "Python Install..." → order: 2, title: "Python Install..."
  days: 8 (example)            →   level_calendar_days: 8 on each row for that level
  len(topics) = N              →   N MongoDB documents (one per session)

  JSON defines WHAT topics exist.
  MongoDB stores THOSE topics WITH their YouTube resources.

  One MongoDB document = one topic in the JSON array.
  order field = index in topics array (1-based).


================================================================
DB FUNCTIONS — db/roadmap_resources.py
================================================================

  get_roadmap(language, level) → list
    → returns all topic documents for language + level
    → sorted by order ascending
    → includes resources array
    → used by learning add handler in STEP 7

  get_topic(language, level, order) → dict
    → single topic document by position

  get_unfetched_topics(limit=50) → list
    → finds documents where fetched_at = null
    → used by initial fetch script

  get_stale_topics(days=30, limit=50) → list
    → finds documents where fetched_at < now - 30 days
    → used by monthly refresh job

  update_resources(doc_id, resources) → bool
    → saves YouTube results to document
    → sets fetched_at = now
    → sets updated_at = now
    → returns True on success

  count_unfetched() → int
    → returns total documents with fetched_at = null
    → used to track seeding progress

  get_sessions_required(language, level) → int
    → returns count of documents for language + level
    → used in feasibility check


================================================================
SEEDING SCRIPTS
================================================================

  Location: Eva_AI_Server/scripts/

  ─────────────────────────────────────────────────────────
  SCRIPT 1 — seed_roadmaps.py
  ─────────────────────────────────────────────────────────

  Purpose:
    Reads roadmaps.json and inserts every topic
    into roadmap_resources collection.
    Runs ONCE. Safe to re-run (skips existing docs).

  What it does:
    1. Load roadmaps.json
    2. For each language in data["topics"]:
         For each level key (basics/intermediate/advanced
           and all specific subtopics):
           For each topic title in level["topics"]:
             Check if document already exists:
               { language: lang, level: lvl, order: idx }
             If not exists → insert:
               {
                 language   : lang,
                 level      : lvl,
                 order      : index + 1,
                 title      : topic_title,
                 level_calendar_days : level["days"] or null,
                 resources  : [],
                 fetched_at : null,
                 created_at : now,
                 updated_at : now
               }
             If exists → skip (idempotent)

  How to run:
    cd Eva_AI_Server
    python scripts/seed_roadmaps.py

  Expected output:
    Seeding roadmap_resources...
    Python basics: 8 topics inserted
    Python intermediate: 14 topics inserted
    ...
    Total inserted: 847 topics
    Already existed: 0
    Done.

  ─────────────────────────────────────────────────────────
  SCRIPT 2 — fetch_resources.py
  ─────────────────────────────────────────────────────────

  Purpose:
    Fetches YouTube resources for all topics
    where resources are empty (fetched_at = null).
    Runs once after seeding, then automatically monthly.

  What it does:
    1. Load YouTube API key from .env
    2. Fetch unfetched topics in batches (50 at a time)
    3. For each topic:
         Call YouTube Data API v3 search endpoint:
           query  = LOCKED (Python worker): roadmap language (goal subject)
                    + session title, unless title already starts with language
                    → build_youtube_search_query() in roadmap_youtube_worker.py
           type   = video
           max    = 3 results
           order  = relevance
         Extract for each result:
           title, url, thumbnail, channel
         Call update_resources(doc_id, resources)
         Wait 0.5 seconds (rate limit safety)
    4. Print progress every 10 topics
    5. If YouTube returns an error (quota, invalid key, network): stop immediately;
       fix the issue and run the script again (no app-side daily cap)

  How to run:
    cd Eva_AI_Server
    python scripts/fetch_resources.py

  Expected output:
    Fetching YouTube resources...
    [1/847] Python Introduction... ✓
    [2/847] Python Installation... ✓
    ...
    On hard API failure, a framed message explains what broke and that you can re-run after fixing.

  Rate limiting:
    A short delay (RESOURCE_FETCH_DELAY_SECONDS, default 0.5s) between successful calls
    reduces burst traffic. Google's own daily quota still applies; if exceeded, the run
    stops on the HTTP error so you are not blindly hammering the API.

  ─────────────────────────────────────────────────────────
  SCRIPT 3 — refresh_job.py (monthly background job)
  ─────────────────────────────────────────────────────────

  Purpose:
    Refreshes YouTube resources for topics
    where fetched_at is older than 30 days.
    Prevents dead/stale video links.

  What it does:
    Same as fetch_resources.py but targets
    stale documents instead of unfetched ones.
    Runs as a scheduled background task.

  Location: Eva_AI_Server/jobs/resource_refresh.py

  Schedule: runs every 30 days
    Uses APScheduler or simple cron
    Runs alongside AI server process

  Integration in main.py:
    from jobs.resource_refresh import start_refresh_scheduler
    start_refresh_scheduler()   ← called at server startup


================================================================
HOW LEARNING ADD HANDLER USES ROADMAP DATA
================================================================

  STEP 7 in learning add handler:

  1. Determine roadmap_key from subtopic mapping
     (basics / intermediate / advanced / specific / general)

  2. Load topics from roadmap_resources:
     topics = get_roadmap(language, roadmap_key)
     → returns ordered list of topic documents
     → each document has title + resources array

  3. sessions_required = len(topics)
     (number of sessions = MongoDB rows for that level; independent of JSON ``days``)

  4. Use topics list to build schedule (STEP 8)
     each topic's title and resources attached to
     corresponding RoadmapTopic document (STEP 10)

  FALLBACK — if resources empty for some topics:
  → create learning goal anyway
  → attach empty resources array
  → background fetch job will fill them
  → user sees resources when they open that topic
  → never block learning creation for missing resources


================================================================
YOUTUBE API SETUP
================================================================

  API used: YouTube Data API v3
  Endpoint: GET https://www.googleapis.com/youtube/v3/search

  Request parameters:
    part      : snippet
    q         : LOCKED — roadmap ``language`` (same as learning-goal subject)
                + ``title`` (session line), unless ``title`` already begins
                with ``language`` (see ``build_youtube_search_query``).
    type      : video
    maxResults: 3
    order     : relevance
    key       : YOUTUBE_API_KEY

  Response fields extracted per result:
    title     : snippet.title
    url       : https://youtube.com/watch?v={id.videoId}
    thumbnail : snippet.thumbnails.high.url
    channel   : snippet.channelTitle

  Environment variable:
    YOUTUBE_API_KEY = (in Eva_AI_Server/.env)

  Error handling:
    API fails → log error → skip topic → continue
    Quota / HTTP error from Google → stop immediately → log / console banner → re-run after fix
    Invalid response → skip → continue


================================================================
COMPLETE SETUP ORDER (ONE TIME)
================================================================

  1. Verify roadmaps.json is complete and correct
     (each level has a ``topics`` array; ``days`` is optional suggested calendar span)

  2. Run seed_roadmaps.py
     → all topics inserted with empty resources

  3. Run fetch_resources.py
     → YouTube resources fetched in one or more runs (re-run if Google returns an error)

  4. Verify with spot check:
     pick 3 random topics
     confirm resources array has 3 YouTube results

  5. Start AI server
     → resource_refresh.py starts as background scheduler
     → auto-refreshes every 30 days

  6. Learning add handler ready to use

SCHEMA ADDITIONS TO EXISTING COLLECTIONS
================================================================

  Learning_Goals — new fields vs original schema:
  ─────────────────────────────────────────────────────────
  roadmap_key     : String    "basics"/"intermediate"/etc
                              which roadmap level was used
  started_at      : Date      null until first topic ongoing
                              set when first topic starts
  completed_at    : Date      null until all topics done
  time_taken_days : Number    completed_at - started_at in days
                              null until completed

  User_Settings — new fields:
  ─────────────────────────────────────────────────────────
  preferred_learning_schedule : Array
    [
      { day: 0, time: "18:00" },   ← Monday 6PM
      { day: 2, time: "14:00" },   ← Wednesday 2PM
      { day: 4, time: "09:00" }    ← Friday 9AM
    ]
    replaces: preferred_learning_time (old enum field)

  NOTE: preferred_learning_schedule set via settings page
  Node.js handles CRUD for this field
  AI server reads it at request start (self-fetch)
  When user sets this in settings → check existing tasks
  for conflicts at those day/time slots before saving
