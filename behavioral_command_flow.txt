================================================================
BEHAVIORAL COMMAND FLOW (FINAL)
AI Server handles all DB operations directly
================================================================

DECISIONS LOCKED
================================================================

  1. Behavioral is READ ONLY — queries Activity_Logs only
  2. No confirmation required — non-destructive
  3. No context manager pending states for behavioral
     → single-turn command, always returns a result
     → if threshold not met → natural reply, no re-prompting
  4. Threshold = 10 completed task logs (from user_settings)
  5. Results always shown in user's local timezone
  6. Gemini formats all results naturally — never raw data
  7. No Google Calendar sync — analytics only
  8. No notifications generated


================================================================
SUB-INTENTS (what behavioral covers)
================================================================

  Model 2 classifies input as "behavioral"
  Then behavioral handler detects sub-intent from entities:

  1. productive_hours
     → "when am I most productive"
     → "what are my best hours on Tuesday"
     → entity: day (optional — if present, filter by weekday)

  2. productive_days
     → "which days am I most focused"
     → "what are my best days"
     → no entities needed

  3. best_time_for_day
     → "find the best time for me on Monday"
     → "when should I schedule on Friday"
     → entity: day (required)

  4. completion_rate
     → "show my completion rate"
     → "how many tasks do I finish on time"
     → no entities needed

  5. productivity_report
     → "show my productivity report"
     → "give me a full analytics summary"
     → no entities needed

  Sub-intent detection logic:
  → if "best time" / "when should I schedule" + day → best_time_for_day
  → if "completion" / "on time" / "finish" → completion_rate
  → if "report" / "summary" / "overview" / "analytics" → productivity_report
  → if "days" / "day of week" → productive_days
  → else → productive_hours (default)


================================================================
NER ENTITIES FOR BEHAVIORAL
================================================================

  day  → specific weekday (Monday–Sunday)
         used in: productive_hours (optional)
                  best_time_for_day (required)

  No other entities needed for behavioral.
  All other data is fetched from Activity_Logs directly.


================================================================
PIPELINE (inside AI Server)
================================================================

  REQUEST RECEIVED FROM NODE.JS
  { message, user_id, session_id, input_type, timestamp }
  ↓

  ↓

  → lowercase only + too_short check
  ↓

  → no pending → continue to Model 1
  ↓

  ↓
  MODEL 2 → behavioral → continue
  ↓
  NER → original cased text
  → extracts: day (if present)
  ↓
  ENTITY SCOPING
  → keep : day
  → drop : everything else
  ↓
  HANDLER — handlers/behavioral/behavioral.py


================================================================
STEP 1 — THRESHOLD CHECK
================================================================

  AI server queries Activity_Logs directly:

  total_completed = db.activity_logs.countDocuments({
    user_id     : user_id,
    action_type : "task_completed"
  })

  threshold = user_settings.analytics_min_tasks_threshold
              (default = 10)

  ┌─────────────────────────────────────────────────────────┐
  │ total_completed < threshold                             │
  │                                                         │
  │ → Gemini generates natural not-enough-data reply:       │
  │                                                         │
  │ EVA: "I need a bit more data to figure out your         │
  │       patterns, Ali. Keep completing tasks and          │
  │       I will start seeing your productive hours soon."  │
  │                                                         │
  │ → STOP — no analytics run                               │
  └─────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────┐
  │ total_completed >= threshold                            │
  │ → detect sub-intent → continue to STEP 2               │
  └─────────────────────────────────────────────────────────┘


================================================================
STEP 2 — SUB-INTENT DETECTION
================================================================

  Detect sub-intent from original message text + entities:

  if "best time" or "when should I schedule"
     or "suggest a time" or "ideal time" in message:
    → sub_intent = "best_time_for_day"
    → requires day entity
    → if day missing → Gemini asks which day
      (only pending state behavioral ever sets — free_text)

  elif "completion" or "on time" or "finish rate"
       or "success rate" or "on-time" in message:
    → sub_intent = "completion_rate"

  elif "report" or "summary" or "overview"
       or "analytics" or "performance" or "habits" in message:
    → sub_intent = "productivity_report"

  elif "days" or "best day" or "which day"
       or "day of week" in message:
    → sub_intent = "productive_days"

  else:
    → sub_intent = "productive_hours"
    (covers: "when am I most productive",
             "what are my peak hours",
             "when do I work best")

  → continue to STEP 3 with detected sub_intent


================================================================
STEP 3 — RUN ANALYTICS QUERY
================================================================

  ── SUB-INTENT: productive_hours ─────────────────────────

  if day entity present (e.g. "best hours on Monday"):
    query = {
      user_id     : user_id,
      action_type : "task_completed",
      day_of_week : weekday_number(day)
    }
  else:
    query = {
      user_id     : user_id,
      action_type : "task_completed"
    }

  logs = db.activity_logs.find(query)

  → group by hour_of_day
  → count completions per hour
  → sort by count descending
  → take top 3 hours
  → also compute was_on_time rate per hour

  result = {
    top_hours : [
      { hour: 18, count: 12, on_time_rate: 0.91 },
      { hour: 10, count: 9,  on_time_rate: 0.78 },
      { hour: 15, count: 7,  on_time_rate: 0.71 }
    ],
    day_filter : day or None,
    total_logs : total_completed
  }

  ── SUB-INTENT: productive_days ──────────────────────────

  logs = db.activity_logs.find({
    user_id     : user_id,
    action_type : "task_completed"
  })

  → group by day_of_week
  → count completions per day
  → compute on_time_rate per day
  → sort by count descending

  result = {
    days : [
      { day: "Tuesday",  count: 18, on_time_rate: 0.89 },
      { day: "Thursday", count: 15, on_time_rate: 0.83 },
      { day: "Monday",   count: 12, on_time_rate: 0.75 },
      ...all 7 days...
    ]
  }

  ── SUB-INTENT: best_time_for_day ────────────────────────

  Requires day entity.
  If missing → set Redis free_text → ask user → stop
  (see Context Manager section)

  logs = db.activity_logs.find({
    user_id     : user_id,
    action_type : "task_completed",
    day_of_week : weekday_number(day)
  })

  → group by hour_of_day
  → count completions per hour
  → sort by count descending
  → get best available hour

  CONFLICT CHECK:
  → query Tasks for that day to find free slots
  → best_hour = top hour with no existing task overlap

  result = {
    day          : day,
    best_hour    : 18,
    on_time_rate : 0.88,
    conflict_free: True
  }

  ── SUB-INTENT: completion_rate ──────────────────────────

  logs = db.activity_logs.find({
    user_id     : user_id,
    action_type : "task_completed"
  })

  total    = len(logs)
  on_time  = count where was_on_time = True
  late     = total - on_time
  rate     = on_time / total * 100

  → also compute weekly trend (last 4 weeks)
  → group by week_number → count per week

  result = {
    total_completed  : total,
    on_time          : on_time,
    late             : late,
    on_time_rate     : rate,
    weekly_trend     : [
      { week: 12, count: 8 },
      { week: 13, count: 6 },
      { week: 14, count: 10 },
      { week: 15, count: 7 }
    ]
  }

  ── SUB-INTENT: productivity_report ─────────────────────

  Runs ALL four queries above combined:
  → productive_hours result
  → productive_days result
  → completion_rate result
  → also: average time_taken_minutes per completed task

  result = {
    top_hours        : [...],
    top_days         : [...],
    on_time_rate     : ...,
    total_completed  : ...,
    avg_time_taken   : ...,
    weekly_trend     : [...]
  }


================================================================
STEP 4 — HANDLE EMPTY RESULTS
================================================================

  If any query returns 0 logs for a specific filter:
  → Gemini generates natural reply explaining no data
    for that specific filter

  Example — best hours on Wednesday but no Wednesday logs:
  EVA: "Looks like you haven't completed any tasks on
        Wednesdays yet, Ali. Give it some time and I'll
        figure out your best hours for that day."

  → STOP


================================================================
STEP 5 — GEMINI FORMATS RESULTS
================================================================

  AI server builds action_context based on sub_intent:

  System instruction:
  "You are EVA, a friendly academic assistant.
   Present analytics results naturally and conversationally.
   Use the user's name. Be specific with numbers and hours.
   Convert hours to 12-hour format with AM/PM.
   Never dump raw numbers — always explain what they mean.
   Keep it concise — max 3-4 sentences.
   Make it feel like a personal insight, not a report."

  ── productive_hours examples ────────────────────────────

  Overall:
  "Your sharpest hours are between 6PM and 8PM, Ali —
   that's when you complete the most tasks and finish
   91% of them on time. Morning at 10AM is your second
   best window."

  Per day:
  "On Mondays you tend to hit your stride around 6PM, Ali.
   You've completed 12 tasks at that hour and 9 out of 10
   were finished on time."

  ── productive_days examples ─────────────────────────────

  "Tuesday and Thursday are your strongest days, Ali.
   You complete the most tasks on those days and your
   on-time rate stays above 85%. Try to schedule
   important tasks on those days."

  ── best_time_for_day examples ───────────────────────────

  "Based on your history, 6PM is your best slot on
   Mondays, Ali — and you have no tasks at that time
   right now, so it's wide open."

  ── completion_rate examples ─────────────────────────────

  "You've completed 42 tasks so far and finished 78% of
   them on time, Ali. Last week was your best week with
   10 completions."

  ── productivity_report examples ─────────────────────────

  "Here's your productivity snapshot, Ali:
   Your peak hours are 6PM-8PM and your best days are
   Tuesday and Thursday. You've completed 42 tasks with
   a 78% on-time rate. Nice consistency over the
   past few weeks."


================================================================
STEP 6 — SAVE MESSAGES AND RETURN
================================================================

  AI server saves user message → Conversation_History
  AI server saves EVA reply   → Conversation_History
  AI server updates Chat_Session (last_message_preview)

  AI server returns to Node.js:
  {
    "status"        : "success",
    "response_text" : "Your sharpest hours are...",
    "notifications" : []
  }

  Node.js returns response to frontend.
  No notifications for behavioral command.
