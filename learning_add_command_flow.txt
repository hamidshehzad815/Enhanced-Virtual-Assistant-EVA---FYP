DECISIONS LOCKED
================================================================

  1. Required entities: topic, start_date, duration
     Optional entities: subtopic, person
  2. Entities validated as soon as extracted (fail fast)
  3. Missing entities asked one by one in order:
     topic → start_date → schedule_choice (number) → duration
  4. Subtopic never asked — optional, general if missing
  5. Predefined JSON roadmaps — no Gemini for generation
  6. 20 supported topics — unsupported gets clean reply
  7. Learning schedules: preferred_learning_schedules[] (labeled, up to 20).
     User must pick schedule via schedule_choice (reply 1..n or 2 for Settings)
     EVEN when only one schedule exists (reply 1 = use, 2 = add different in Settings)
  8. No schedules in settings → tell user → stop
  9. Duration = calendar days, sessions = learning days
     that fall within that duration
  10. Feasibility check: available sessions >= roadmap sessions
  11. Schedule built sequentially — topic 1 to first
      learning day, topic 2 to second, and so on
  12. No conflict check during schedule building —
      conflicts handled in learning update command
  13. Goal created for owner immediately
      Collaborator invite sent — accept creates goal for them
      reject/no response (48h) → owner goal unchanged
  14. YouTube resources fetched from roadmap_resources DB
      never fetched live during learning add
  15. Silent goal tracking: started_at, completed_at,
      time_taken_days recorded automatically
  16. Topic completion via push notification action,
      app popup, or chat command — 3 ways
  17. Goal status transitions:
      active → paused / cancelled / completed (auto)
      paused → active / cancelled
      completed → terminal
      cancelled → terminal
  18. Duplicate goal logic:
      specific subtopic active → different subtopic allowed
      general/full roadmap active → block same language
      exact same subtopic active → block
  19. Task reminders use default_reminder_minutes from User_Settings (default 30)
  20. learning_schedule_id stored on goal; schedule cannot be reused on another
      active goal for same user (used_learning_schedule_ids)
  21. Collaborator notifications: learning_collaboration_invite; owner gets
      learning_collaboration_response on accept/reject (backend)
  22. Duration under 7 days in one shot → error (not Redis re-prompt)
  23. All EVA replies natural, specific, use user name

NER ENTITIES FOR LEARNING ADD

  Extracted from original cased text:
    topic      → programming language or database name
    subtopic   → level or specific area within topic
    start_date → when to begin learning
    duration   → how long to spend on this goal
    person     → collaborator username

  Examples:
    "I want to learn Python basics in 2 weeks"
      → topic: "Python", subtopic: "basics",
        duration: "2 weeks"

    "learn JavaScript starting Monday for 1 month"
      → topic: "JavaScript", start_date: "Monday",
        duration: "1 month"

    "create a Python OOP roadmap starting next week"
      → topic: "Python", subtopic: "OOP",
        start_date: "next week"

    "I want to learn MySQL in 3 weeks with Ahmed"
      → topic: "MySQL", duration: "3 weeks",
        person: "Ahmed"

    "learn Python"
      → topic: "Python"
        (start_date and duration missing — will be asked)

================================================================
STEP 8 — BUILD SCHEDULE
================================================================

  Sequential assignment — topic 1 to first available
  learning day from start_date, topic 2 to next, etc.

  Algorithm:
  ─────────────────────────────────────────────────────────
    schedule     = []
    current_date = start_date
    topic_index  = 0
    topics       = roadmap topics list

    while topic_index < len(topics):
      weekday = current_date.weekday()

      if weekday in learning_days:
        time = schedule[weekday].time
        session_datetime = combine(current_date, time)

        schedule.append({
          topic_index    : topic_index + 1,
          title          : topics[topic_index].title,
          resources      : topics[topic_index].resources,
          scheduled_date : session_datetime,
          status         : "pending"
        })
        topic_index += 1

      current_date += 1 day

    end_date = schedule[-1].scheduled_date.date()

  NOTE: no conflict check here —
  conflicts handled in learning update command

================================================================
TOPIC COMPLETION FLOW
================================================================

  Three ways user marks a topic complete:

  1. Push notification action button:
     → reminder fires before session
     → notification has "Mark Complete" action
     → tap → EVA marks topic complete

  2. App popup:
     → user opens app after missed session
     → popup: "Did you complete [topic] on [date]?"
     → yes → mark complete
     → no  → mark skipped or keep pending

  3. Chat command:
     → "I completed today's Python session"
     → EVA detects completion intent
     → marks current pending topic as complete
     → updates Learning_Goal.completed_topics + 1
     → updates started_at if first topic
     → if last topic:
         update Learning_Goal.status = "completed"
         update Learning_Goal.completed_at = now
         calculate time_taken_days =
           completed_at - started_at in days
         EVA: natural congratulations reply


================================================================
GOAL STATUS TRANSITIONS
================================================================

  active → paused
    triggered by: chat command "pause my Python learning"
    sets: status = "paused", paused_at = now
    all pending topic tasks stay as-is

  paused → active
    triggered by: chat command "resume my Python learning"
    sets: status = "active", paused_at = null

  active → cancelled
    triggered by: chat command "cancel my Python learning"
    sets: status = "cancelled", is_deleted = true
    soft deletes all pending roadmap topic tasks

  active → completed
    triggered by: system — when last topic marked complete
    sets: status = "completed"
          completed_at = now
          time_taken_days = completed_at - started_at

  completed → terminal (no further transitions)
  cancelled → terminal (no further transitions)

REMINDER FLOW
================================================================

  Node.js reminder job fires at:
    topic.scheduled_date - settings.default_learning_reminder_minutes

  default_learning_reminder_minutes = 15 (from User_Settings, user-configurable)
  independent of default_reminder_minutes (task reminders)
  user can change in settings without affecting tasks

  Reminder notification:
  "Your [topic title] session starts in 30 minutes, Ali."

  After session time passes:
  If topic still pending → app shows popup on next open
  "Did you complete [topic] on [date]?"
