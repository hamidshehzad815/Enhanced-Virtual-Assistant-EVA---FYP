PHASE 25 — CONTEXT MANAGER FOR UPDATE
================================================================

Goal: Context manager handles all 4 update-specific states
      including the two-phase (identify then confirm) flow.

  AI Server
  ─────────────────────────────────────────────────────────

  [x] Add stage-aware routing to context_manager.py:

      When pending intent = "update", route by stage:

      stage = "identify" + expected = "free_text":
        → treat reply as task_name identifier
        → merge as task_name into entities
        → clear Redis
        → re-enter handler from STEP 1 (identify)

      stage = "identify" + expected = "number":
        → run Model 1 first
        → confirm or continue as per standard number flow
        → on valid number:
            → select task
            → if update fields already in entities:
                update Redis to yes_no stage="confirm"
                Gemini asks for confirmation
            → if no update fields:
                update Redis to free_text stage="what_to_update"
                Gemini asks what to change

      stage = "what_to_update" + expected = "free_text":
        → SKIP Model 1
        → pass reply through NER
        → extract update fields from reply
        → if fields found:
            merge into entities
            clear Redis
            re-enter handler at STEP 5 (validate fields)
        → if NER finds nothing:
            Redis stays (TTL resets)
            Gemini: "I didn't catch that. Try saying
                     'priority to high' or 'move to Tuesday'."
            STOP

      stage = "confirm" + expected = "yes_no":
        → run Model 1 first
        → standard yes/no flow
        → yes → clear Redis → STEP 8 (perform update)
        → no  → clear Redis → cancellation reply

  [x] Write unit tests for update context manager:
      → free_text state 1: reply treated as task_name
      → number state 2: valid number selects task
      → number state 2: update fields present → goes to confirm
      → number state 2: no update fields → goes to what_to_update
      → free_text state 3: NER extracts update fields
      → free_text state 3: NER finds nothing → ask again
      → yes_no state 4: yes → update proceeds
      → yes_no state 4: no → cancel
      → cancel in any state → Redis cleared
      → new command in yes_no state → blocked
      → TTL expiry → fresh start
