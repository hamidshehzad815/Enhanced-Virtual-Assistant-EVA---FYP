================================================================

DECISIONS LOCKED
================================================================

  1. Deletes entire learning goal only
     No individual topic deletion
     Topic skipping → learning update (separate command)
  2. User must confirm before any deletion happens
  3. Soft delete only — is_deleted = true, never hard delete
  4. Match logic same as scheduling delete:
       0 found   → not found reply → stop
       1 found   → yes/no confirmation
       2-5 found → numbered list → pick one or "all"
       6+ found  → too broad → narrow down
  5. Bulk delete ("all") supported with separate confirm
  6. Pending topics → soft deleted
     Pending tasks → soft deleted
     Completed topics → kept for history
     Completed tasks → kept for history
  7. Pending calendar events → removed (non-blocking)
     Completed calendar events → kept
  8. Activity logs → kept always
     goal_deleted log inserted once per deletion
  9. Conversation history → kept always
  10. Schedule slot → automatically freed (no action needed)
  11. Collaborator's cloned goal → untouched
      Collaborator notified with new notification type:
      learning_goal_deleted
  12. Active, paused, completed goals → all can be deleted
  13. Ongoing topic/task at time of deletion → soft deleted
      Delete always wins
  14. Google Calendar failure → log silently, never block
  15. All EVA replies natural, specific, use user name
  16. "cancel" keyword = flow cancellation not goal deletion


================================================================
NER ENTITIES FOR LEARNING DELETE
================================================================

  Extracted from original cased text:
    topic    → language or database name (identifier)
    subtopic → specific roadmap level or area (narrowing)

  No other entities needed:
    duration   → not applicable for identification
    start_date → not applicable for identification
    person     → not applicable for identification

  Examples:
    "delete my Python roadmap"
      → topic: "Python", subtopic: null
      → finds ALL Python goals

    "delete Python basics"
      → topic: "Python", subtopic: "basics"
      → finds Python goals where roadmap_key = "basics"

    "remove my Python lists roadmap"
      → topic: "Python", subtopic: "lists"
      → finds Python goal where roadmap_key = "lists"

    "cancel my MySQL learning"
      → topic: "MySQL", subtopic: null
      → finds ALL MySQL goals

    "delete my roadmap" (no topic)
      → no entities → State 1 → ask user


================================================================
SUBTOPIC MAPPING (same as learning add)
================================================================

  Step 1: check SUBTOPIC_ALIAS_MAP
    "beginner" → "basics"
    "oop"      → "object oriented programming"
    etc.

  Step 2: regex search against roadmap keys
    for that specific language in roadmap JSON

  Step 3: no match → subtopic = null
    (search all goals for that topic)

  ↓

  ↓
  MODEL 2 → learning_delete → continue
  ↓

  ↓

  ↓
  HANDLER — handlers/learning/delete.py

================================================================

  │   }                                                     │
  │ )                                                       │

  │     goal_id    : goal_id,                               │

  │   {                                                     │
  │     is_deleted : true,                                  │

   Your 3 completed sessions are still saved."

  Single goal deleted (no progress):
  "Done Ali — Python functions has been removed
   from your learning plan."

  Multiple goals deleted (bulk):
  "All 2 Python goals have been removed, Ali.
   Any completed sessions you had are still saved."

  Cancelled:
  "No problem Ali, nothing was deleted."

  Not found:
  "I couldn't find any Python learning goals, Ali.
   Double check the topic or subtopic name?"


================================================================
STEP 8 — SAVE MESSAGES AND RETURN
================================================================

  AI server saves user message → Conversation_History
  AI server saves EVA reply   → Conversation_History
  AI server updates Chat_Session (last_message_preview)

  AI server returns to Node.js:
  {
    "status"        : "success",
    "response_text" : "Done Ali — Python basics...",
    "notifications" : [ ...collaborator payloads if any... ]
  }

  Node.js:
  → inserts notifications into DB
  → dispatches FCM push to collaborator(s)
  → sends email if enabled
  → returns response_text to frontend


================================================================
SPECIAL CASES
================================================================

  No goals exist at all for user:
  → 0 found path → not found reply
  "I couldn't find any Python learning goals, Ali."

  Completed goal deleted:
  → allowed — same flow as active/paused
  → completed topics and tasks still kept
  "Done Ali — Python basics (completed) has been removed
   from your history."

  Paused goal deleted:
  → allowed — same flow
  "Done Ali — Python basics has been removed.
   It was paused with 3 of 8 sessions done."

  Ongoing topic at time of deletion:
  → soft deleted along with other pending topics
  → delete always wins
  → no special message needed

  Google Calendar API failure:
  → log silently
  → deletion proceeds regardless
  → user never sees calendar error

  Bulk delete — activity log:
  → one goal_deleted log per goal
  → if 3 goals deleted → 3 activity logs inserted
